# Tokyo OpenTripPlanner Routing

This project uses OpenTripPlanner (OTP) to provide transit routing for Tokyo using GTFS data generated by the tokyo-gtfs2 project.

## Features

- 🚃 Multi-modal routing (rail + walking)
- 🕐 Time-based route planning
- 🗺️ Interactive web interface
- 🔌 REST API for programmatic access
- 🚶 Walking directions with street network
- 📊 Multiple route options with transfers

## Prerequisites

- Docker and Docker Compose
- Python 3.8+ (for the example scripts)
- At least 4GB of available RAM
- ~500MB disk space for OSM data

## Quick Start

### 1. Download OpenStreetMap Data

First, download the street network data for walking directions:

```bash
./download-osm-data.sh
```

This downloads the Kanto region OSM data (~400MB) which includes Tokyo.

### 2. Start OpenTripPlanner

```bash
docker-compose up -d
```

This will:
- Download the OTP Docker image
- Build the routing graph from GTFS + OSM data (takes 5-10 minutes)
- Start the OTP server

Watch the logs to see progress:
```bash
docker-compose logs -f
```

### 3. Access OTP

Once running, you can access:
- **Web Interface**: http://localhost:8080/
- **API Documentation**: http://localhost:8080/otp/

## Using the Route Finder

### Python Example

```bash
cd examples
pip install -r requirements.txt
python route_finder.py
```

This will find routes from Tokyo Station to Shibuya.

### Direct API Usage

Find a route using the REST API:

```bash
curl "http://localhost:8080/otp/routers/default/plan?fromPlace=35.6812,139.7671&toPlace=35.6580,139.7016&mode=TRANSIT,WALK"
```

### API Parameters

Key parameters for route planning:
- `fromPlace`: Start coordinates (lat,lon)
- `toPlace`: End coordinates (lat,lon)
- `date`: Date (YYYY-MM-DD)
- `time`: Time (HH:MM)
- `arriveBy`: true/false (arrival vs departure time)
- `mode`: TRANSIT,WALK
- `maxWalkDistance`: Maximum walking distance in meters
- `numItineraries`: Number of alternative routes

## Station Coordinates

To find routes between stations, you need their coordinates. You can get these from the GTFS stops.txt file:

```python
import pandas as pd
import zipfile

with zipfile.ZipFile('data/tokyo_rail.zip') as zf:
    with zf.open('stops.txt') as f:
        stops = pd.read_csv(f)
        
# Find a station
shibuya = stops[stops['stop_name'].str.contains('Shibuya')]
print(shibuya[['stop_name', 'stop_lat', 'stop_lon']])
```

## Configuration

The `otp-config.json` file contains settings for:
- Transfer times between modes
- Walking speeds
- Service date ranges
- Routing preferences

Key settings:
- `boardTimes`: Time to board vehicles (seconds)
- `walkSpeed`: Walking speed (m/s)
- `transferPenalty`: Extra cost for transfers
- `numItineraries`: Default number of routes returned

## Troubleshooting

### OTP Won't Start
- Check Docker logs: `docker-compose logs otp`
- Ensure you have enough RAM (4GB recommended)
- Verify GTFS and OSM files exist in `data/`

### No Routes Found
- Check that both stations are in the GTFS data
- Verify the date/time is within service calendar
- Try increasing `maxWalkDistance`

### Slow Performance
- First startup takes time to build the graph
- Graph is cached after first build
- Consider giving Docker more RAM

## Advanced Usage

### Custom Walking Speed
```python
result = finder.find_route(
    from_lat, from_lon, to_lat, to_lon,
    walkSpeed=0.8  # Slower walking
)
```

### Wheelchair Accessible Routes
Add `wheelchair=true` to API requests.

### Avoid Specific Routes
Use `bannedRoutes` parameter to exclude certain lines.

## Data Updates

To update with new GTFS data:
1. Replace `data/tokyo_rail.zip`
2. Restart OTP: `docker-compose restart`
3. OTP will rebuild the graph automatically
